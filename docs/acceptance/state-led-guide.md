# 状态与指示灯说明修正

日期：2026-10-26（Asia/Shanghai）。基线：v1.5.1。用户授权补齐 ERR 灯态并改进理解与交互，调用 gui-development。

## 需求与依据

- 默认无错误时，ERR应保持熄灭；PREOP/SAFEOP并不自动表示故障，不能为了让灯变化而改变这条规则。
- 补齐启动错误快闪、严重通信/控制器错误常亮，六种ERR类型均可直接选择，并显示对应节奏及解释。
- 区分正常BOOT升级分支与启动错误；过程数据/SM看门狗双闪与部分Beckhoff ESC的PDI看门狗常亮分别说明。
- 来源：[Beckhoff Register Description V3.3 §2.5.5](https://download.beckhoff.com/download/Document/io/ethercat-development-products/ethercat_esc_datasheet_sec2_registers_v3.3.pdf#page=37)、[ESC Technology V2.5 §15.2](https://download.beckhoff.com/download/document/io/ethercat-development-products/ethercat_esc_datasheet_sec1_technology_v2.5.pdf#page=132)、[Novanta灯效节奏](https://drives.novantamotion.com/den-safe-net/led-signals-reference)。正式指示与标识规范为ETG.1300，本次按上述公开实现资料核对，不声称取得并认证全部会员规范。

## 实现边界与方案

沿用基础概念工作台、AL步骤和既有URL参数。六个ERR场景使用单选组，选中后回到周期起点并暂停，显示“为何常灭/当前故障/如何播放”。RUN由所选AL状态决定，ERR由教学故障决定；该对照不模拟真实故障引起的状态迁移。

```text
AL状态 -> RUN模式 -----+
ERR场景 -> ERR模式 ----+-> 共用循环窗口 -> 亮带、灯、游标、读数
                      +-> 选中情景的短解释与硬件范围
```

原1600ms固定窗口不是所有节奏的完整周期：单闪周期1200ms，播放超过窗口后相位会错位。新纯模型使用两种所选变化节奏的共同周期，并将窗口扩展到至少1600ms；常亮/常灭不引入额外周期。两条轨道、游标与灯态统一使用同一窗口内时刻。

## 复验记录与证据

- 原问题复现：旧模型在1600ms时，单闪灯为灭，但旧游标回到0ms的亮带；新模型让单闪/双闪共用4800ms循环，不再错误折返。
- 新增 `tests/state-led.test.js` 五项测试，包含36种模式组合的多周期检查；完整测试由157项增至162项。
- 未识别的ERR链接显示错误面板，六个选项保持未选择；可通过选择合法类型或面板恢复，不推断成无错误。
- 每次切换故障或RUN模式回到0ms暂停；再次切回旧状态不会恢复先前播放。整体“恢复教学值”同时清理局部演示进度。
- 后台启动预览命令被自动审批拦截，仅返回策略拒绝；没有重试该后台命令。改用工具管理的前台终端会话运行既有预览脚本，完成所有实际界面检查。本机入口为 `http://127.0.0.1:4181/`。
- 390px截图使用明确CSS视口的捕获区域，避开系统150%缩放引起的默认截图裁切；未把截图表面尺寸问题误判为应用溢出。
