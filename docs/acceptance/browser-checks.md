# 实际浏览器检查记录

环境：Codex 内置 Chromium，本地 Vite 页面；2026-10-24。通过真实表单输入、按钮点击、页签切换、滚动和截图观察验证。最终生产候选另列复验记录。

## 已执行：五个计算器

- PDO：输入 `0x70000110` 实际得到 0x7000 / 0x01 / 16 bit；输入0显示位长错误且撤下结果；切换编码输入65535/255/255得到 `0xFFFFFFFF`；点击复制并读取剪贴板验证完全一致。
- 位布局：默认16+32+8=56bit/7B；将首字段改3bit、开启同一SSC对象附加检查，再添加8bit字段，得到51bit/7B/余5bit；准确显示WORD非对齐和小成员跨字节条件，未自动添加padding。第四字段改0触发错误；删除与重置恢复有效结果。
- 看门狗：默认Divider2498/Count1000显示100ms；SM Count=0显示“已禁用”而PDI保持；单位改µs显示100000µs；Divider65536触发16bit范围错误；重置恢复。
- ControlByte：0xE4在传统模型下给bit7条件性提醒；选择已支持Sequential后显示顺序模式，不再误报保留位；0x26默认字段与位图一致。已观察桌面与390px窄屏实际表格、字段和提示。
- SM：默认4通道分配328B；SM3地址改0x1120时，准确提示SM2第三缓冲区重叠；载入32bit官方示例A=0x1003/L=0xFA，实际显示单buffer256B、3buffer768B和完整物理范围[0x1000,0x1300)。

## 已发现并修复

- 计算器中隐藏无障碍标签的绝对定位曾扩大滚动范围，导致应用顶栏向上滚出。根容器确定100%高度、应用外层采用 overflow:clip，隐藏标签明确定位到top/left=0。经再次点击深处控件复验，1280×720与390×844下document没有超出viewport，应用scrollTop=0、headerTop=0，内容仅在main内滚动。
- 窄屏ControlByte表“10 / 01”的两bit值被拆成两行，已对位字段和值列禁用换行；表格只在自己的滚动容器中横向滚动。
- 列表的反向关系不能机械添加“被”，已处理“被引用→引用”等方向、对称关系和其他反向关系显示，消除“被被编码”。

## 最终导航验收

用户在首次预览后要求主入口按工具/文件实体，且SSC保留原树层级。本记录此前主题导航不计作最终导航通过；实体导航完成后需重新检查。

## 最终候选复验：通过

生产入口：http://127.0.0.1:4181/。最终脚本 `index-BvVAG3Ma.js`，样式 `index-Di2D-lfA.css`。

- 首屏默认SSC Tool概览。SSC的9个可选择节点（含Application父组和ProcessData子组）全部逐项点击，显示正确分组及条目；Compiler显示版本相关的分组说明，不伪造宏。
- 应用定义文件的“对象字典字段”15项与“设备与模块”1项均实际进入；ESI的身份6、通信13、字典3、模块3、EEPROM2项分组均实际进入，概览和分组名称与内容一致。
- 跨实体链：SSC MAX_PD_OUTPUT_SIZE → ESI RxPdo；应用定义Access → ESI Objects → 应用定义Index；基础概念PDO Mapping → ESI Entry。每次目标、目录高亮及URL一致。浏览器返回恢复SSC原ProcessData分组。
- 在应用定义入口全局搜ControlByte，得到ESI与基础概念3项；Enter打开结果，返回恢复原查询。未知词出现明确空态，清除按钮恢复。
- 收藏MAX_PD_OUTPUT_SIZE后刷新保持；进入收藏后取消，出现空收藏引导。复制条目链接和配置示例实际核对剪贴板值。
- 首次直达CoeWrite链接后，最近查阅的首项就是CoeWrite。独立复核发现的初次深链漏记已修复。
- 窄屏Hardware分组列表 → 第一项HW_ACCESS_FILE → 浏览器返回，恢复列表；非第一项ESC_32BIT_ACCESS → 页面返回结果也恢复原列表。URL明确保存pane=list/detail，独立复核发现的同首项历史丢失已修复。
- Ctrl+K从说明页进入全局搜索并实际聚焦输入；条目和计算器页签通过方向键/Home切换；移动目录展开、Esc关闭、图标名称与焦点样式已观察。
