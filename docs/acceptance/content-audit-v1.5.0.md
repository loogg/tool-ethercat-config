## 已确认问题

### C01 · 模块化示例错误定义 0xF000

定位：`src/data/esi-examples.js:41`。

现状：`Teaching_Modules.xml` 把 `0xF000 Modular Device Profile` 定义成 `UDINT / 32 bit` 单值，没有子项。实际解析得到 `type=UDINT, bits=32, members=0`。

依据：[Beckhoff 标准对象表：F000](https://infosys.beckhoff.com/content/1033/el3773/2044036363.html) 的 `:00` 为 UINT8 结构元数据，`:01` 为 UINT16 模块索引距离，`:02` 为 UINT16 最大模块数。这里核对结构与字段含义，产品的具体模块数不作为通用值。

影响：会让新手把 MDP 组织信息理解为一个 32 bit 业务参数；也与本工具应用定义示例中的 F000 RECORD 互相矛盾。

修正要求：使用复合类型和相应子项；教学距离与模块数需与当前 Slots 示例一致，并验证应用定义与 ESI 两侧的结构语义。

### C02 · 修订 2 的默认 SM 长度与 PDO 描述不一致

定位：`src/data/esi-examples.js:40`，共用 `sm` 模板位于文件第 8–13 行。

现状：修订 2 的必选 RxPDO 引用一个 32 bit 成员，需要 4 Byte；Outputs 的 DefaultSize 仍为 2 Byte。同时 Inputs 保留 Enable=1、DefaultSize=2，当前修订却没有 TxPDO 描述。

依据：[ET9300 §16.1](https://download.beckhoff.com/download/Document/io/ethercat-development-products/an_et9300_v1i10.pdf#page=133) 的活动长度计算；当前工具自身也区分默认长度和最终在线配置。

影响：教学默认组合前后不一致。不能据此断言所有主站必然无法启动，因为主站可能重算过程数据 SM 长度；但工具不应给出这种未说明差异的默认示例。

修正要求：为不同修订生成一致的 SM/PDO 默认组合。无输入方向的示例应明确表达未使用的通道；核验活动组合、默认长度和启用状态。

### C03 · 双向 PDO 可映射属性丢失一个方向

定位：`src/lib/esi-display-model.js:80`；字段写法参考位于 `src/data/esi-field-rules.js` 的 PdoMapping 规则。

现状：仅值严格等于 `T` 时选择输入关系，其他值全部选择输出关系。实际调用显示函数的结果：`R → pdo-output:app`，`T → pdo-input:app`，`RT/TR → pdo-output:app`。

依据：本机已有 `EtherCATBase.xsd` 的 ObjectType 与 SubItemType 均允许 `T`、`R`、`TR`、`RT`。当前工具的字段参考也已经列出了 RT，但未列 TR。

影响：打开具有 RT/TR 的 ESI 时，关联只反映 Rx 一侧，遗漏 Tx 一侧；这是显示推导错误，不表示原 XML 被修改。

修正要求：分别识别 R/T；RT 和 TR 同时展示两种能力。未知值保留未解析，不能默认为 Rx。同步补充 TR 写法与方向测试。

## 应补充的实现条件

### S01 · OP_PD_REQUIRED 与首次过程输出

定位：`src/data/ssc.js:146`。

现有“0 可以不等待首帧进入 OP”解释只覆盖进入条件。已有 SSC 5.13 头文件同时说明了首次过程数据与看门狗监测的关系；当前说明没有呈现该条件。

应补充首次输出标志、栈检查路径与 ESC 硬件计时的区别。不能简单写成“进 OP 立即按同一规则监测”，也不能笼统写成“所有硬件看门狗都由此宏启动”。具体行为需绑定实际 SSC 版本与硬件/软件看门狗路径。

### S02 · 状态转换宏值不一定等于内部等待时间

定位：`src/data/ssc.js:154`、`:161` 及 AL 时序教学。

已有 SSC 5.13 移植源码在 AL_ControlInd 中对状态等待计数减去 10%，并在 PREOP→SAFEOP 与 SAFEOP→OP 使用同一超时宏。头文件的旧注释仍提及 50 ms，说明仅依赖注释也会出错。此行为仅作为本机该版本的代码证据，不上升为全 SSC 规则。

当前条目已提示“以实际版本为准”，不判作宏值本身错误；但更适合补充“对外声明时限 / 内部提前响应计数 / 主站超时”三个层次。独立教学的允许等待时间不能直接标成任意版本宏的精确执行结果。
